# Toolsiano — инструкция

Новая версия находится целиком в этой папке. Старый сайт не изменён. В GitHub нужно переносить содержимое `new`, а не родительскую папку вместе с `old`.

## Страницы скачивания и статистика

Добавлены `/ru/download/` и `/en/download/`: Windows/macOS/Linux, инструкции, версия, размер, SHA-256 и история выпусков. Система определяется локально. Страницы включены в навигацию, sitemap и офлайн-копию. Десктопная версия Tauri находится в src-tauri; установщики ещё не опубликованы: страница честно показывает этот статус. Браузерный офлайн-доступ остаётся отдельной возможностью.

После публикации стабильных установщиков в публичном GitHub-репозитории:

```sh
npm run desktop:sync -- --repo OWNER/REPOSITORY
npm run build
```

Сохраните обновлённый `src/data/desktop-releases.json` в Git. Поддерживаются `.exe`, `.msi`, `.dmg`, `.AppImage`, `.deb`. Имена файлов должны содержать архитектуру `x86`/`i686`/`ia32`, `x64`/`x86_64`/`amd64`, `arm64`/`aarch64` или `universal`; обязательна контрольная сумма `sha256:` в метаданных GitHub. Черновики, предварительные выпуски, исходники, подписи и архивы обновлений исключаются. Ошибка не заменяет прежний каталог. Проверяйте сборки и подписи перед выпуском; системные требования и примечания размещайте в описании GitHub-релиза. Посетители не обращаются к GitHub API.

Для просмотра статистики на своём компьютере:

```sh
npm run downloads:stats -- --repo OWNER/REPOSITORY
```

Откройте `work/download-statistics/index.html`. Отчёт показывает суммарные скачивания по версиям, ОС и файлам. Каждая команда сохраняет JSON-снимок с датой и ID файлов. Папка исключена из Git, сайта, архива исходников и Docker-контекста. База и учётные данные для публичного репозитория не требуются; действуют ограничения GitHub API. Счётчики GitHub публичны, хотя ваш отчёт хранится локально. Разница снимков — прирост между наблюдениями, а не точная статистика по дням. Замена или удаление файла может сбросить счётчик. Повторные загрузки и обновления включены; это не число людей или установок. Автоматический опрос, публичный счётчик и телеметрия не добавлены. При скачивании действует политика приватности GitHub.

## Запуск

Нужны Node.js 24 LTS и npm. Для локальной работы Docker не требуется.

```sh
npm ci --ignore-scripts
npm run dev
```

Откройте http://127.0.0.1:4321. Команда собирает обе языковые версии и следит за изменениями в `src` и `public`. После успешной пересборки обновите страницу.

Проверки и готовая сборка:

```sh
npm run check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

Готовый сайт — в `dist`. Команда `preview` обслуживает существующую сборку с защитными заголовками. Это локальный сервер проверки, а для VPS используется Caddy.

## Языки

- На `.com` вход без языкового префикса открывает `/en/`.
- На `.ru` открывается `/ru/`.
- Явные адреса `/en/` и `/ru/` работают на обоих доменах и имеют приоритет.
- Переключатель сохраняет текущий инструмент, но не переносит файлы и введённые данные. Сохраните результат перед переходом.
- На localhost начальный язык — русский.
- Нет определения страны по IP, языковых cookie и междоменных идентификаторов.

Для поисковых систем основной английский адрес — `toolsiano.com/en/...`, русский — `toolsiano.ru/ru/...`. Генерируются canonical, взаимные hreflang и отдельные карты сайта. При других доменах задайте `PUBLIC_EN_ORIGIN` и `PUBLIC_RU_ORIGIN` во время сборки. Изменение схемы `.com/.ru` также требует обновить правила Caddy.

Обе языковые версии доступны на обоих доменах для переключения и офлайн-работы. Междоменный canonical поддерживается Google, но Яндекс может его игнорировать: перед запуском нужно учитывать риск языковых дублей. Для строгого объединения понадобятся междоменные 301 и согласованное изменение офлайн-копии. Страницы ошибок возвращают 404, содержат `noindex` и исключены из sitemap и предварительного офлайн-кеширования. Старые постоянные адреса инструментов перенаправляются кодом 301.

Переводы находятся в `src/i18n/en.json`. Английские HTML-страницы создаются во время сборки; внешние переводчики при работе приложения не используются. Сборка и тесты проверяют наличие переводов статического интерфейса и строк клиентских сообщений.

## Что входит

11 инструментов: пакетный редактор изображений, изображения в PDF, редактор страниц PDF, сжатие, очистка метаданных, пароли, создание QR, чтение QR, экспорт PDF в изображения/текст, подготовка сканов и водяные знаки PDF.

В редакторе изображений и водяных знаках PDF доступны текст и логотип: девять позиций, ширина в процентах, непрозрачность, отступ, поворот и повторение по всей площади. Изображения показывают изменения сразу на первом файле; PDF показывает первую выбранную страницу по кнопке предпросмотра, после чего настройки знака обновляют его сразу. Пакетная обработка применяет общие настройки к каждому изображению. Логотипы PNG/JPEG/WebP ограничены 5 МБ и 2 мегапикселями; прозрачный PNG сохраняет прозрачность. Логотип хранится только в памяти вкладки и удаляется отдельной кнопкой или при закрытии вкладки. В PDF одно изображение логотипа используется на нескольких страницах, текст и векторное содержимое сохраняются. Водяные знаки не предназначены для скрытия конфиденциальных данных.

Добавлены целевой вес JPEG с ограниченным подбором качества, сравнение первого изображения, скачивание результатов ZIP, диапазоны страниц и очистка результатов. Миниатюры PDF создаются по мере прокрутки. Остановка обработки действует на границах шагов; для немедленного завершения вычислений закройте вкладку.

Pomodoro, ударения, SEO, заметки и вероятности удалены; их маршруты возвращают 410. OCR и HEIC отложены. Отдельный устанавливаемый дистрибутив и счётчик скачиваний не реализованы: есть браузерный офлайн-режим без телеметрии.

## Ограничения ресурсов

До 25 МиБ на файл, до 30 файлов и 100 МиБ исходных данных на задание. Для растровых операций — до 12 Мп на узком экране и 24 Мп на остальных; PDF — до 50/100 страниц соответственно. Ширина экрана служит только консервативной подсказкой, а не измерением свободной памяти. Результаты ограничены суммарно 100 МиБ.

Работа последовательная. Ограничения снижают риск, но не гарантируют работу любого документа на слабом устройстве. PDF, кодирование изображений и создание итогового ZIP требуют памяти. Полные тесты пикового потребления RAM на телефонах не проводились.

JPEG и PNG очищаются без перекодирования пикселей, если ориентация позволяет. ICC-профиль JPEG удаляется; цвет нужно проверить. WebP и повёрнутые JPEG перекодируются; APNG не поддерживается. Сжатие не гарантирует уменьшение размера, а целевой вес может потребовать уменьшения ширины. Растеризация PDF теряет текстовый слой и ссылки. Подписанные и защищённые PDF не поддерживаются для правки. Водяной знак не является подписью или надёжным скрытием исходного текста.

## Размещение на VPS

Нужны Linux VPS, Docker Engine, Compose, DNS обоих доменов на сервер и доступные TCP-порты 80/443. UDP 443 можно открыть для HTTP/3. Если порты заняты другим веб-сервером, сначала согласуйте схему размещения.

```sh
git clone <АДРЕС-ВАШЕГО-РЕПОЗИТОРИЯ> toolsiano
cd toolsiano
printf 'SITE_ADDRESS=toolsiano.com, toolsiano.ru\n' > .env
docker compose up -d --build
```

Caddy автоматически обслуживает оба домена и получает публичные HTTPS-сертификаты. Тома `caddy_data` и `caddy_config` нужно сохранять. В рабочем контейнере нет Node.js, Битрикса, PHP и базы данных: только Caddy и статические файлы. Node используется на стадии сборки.

Для обновления: `git pull`, затем `docker compose up -d --build`. Для отката используйте предыдущий проверенный Git-тег и пересоберите. Конфигурация содержит перенаправления, локализованные 404, отдельные sitemap/robots и CSP. `SITE_ROOT` нужен только для проверки нативным Caddy; внутри контейнера оставьте `/srv`.

GitHub Actions проверяет типы, алгоритмы, браузерные сценарии и сборку, сохраняя `dist` как артефакт. Автоматического доступа к VPS нет. Ключи размещения добавляются только через GitHub Secrets, когда потребуется отдельный процесс деплоя. Доменов и репозитория эта задача не регистрирует и не публикует.

## Офлайн-копия и проверка браузеров

Пункт «Офлайн-доступ» внизу страницы открывает окно состояния. Копия сохраняется в Cache Storage текущего браузера и домена, а не файлом в «Загрузки». В окне можно сохранить, обновить или удалить копию; удаление сохраняет выбранную тему. Дата и версия копии хранятся локально. Новая копия заменяет старую после успешной загрузки всех ресурсов. Копии двух доменов независимы. Ярлык PWA можно добавить средствами поддерживающего браузера; это отдельное действие от сохранения офлайн-копии.

Для проверки других движков установите `npx playwright install firefox webkit` и задайте `PLAYWRIGHT_BROWSER=firefox` или `PLAYWRIGHT_BROWSER=webkit` перед `npm run test:e2e`. По умолчанию используется Chromium; `PLAYWRIGHT_CHROMIUM_EXECUTABLE` позволяет указать установленный Chrome, а `PLAYWRIGHT_BASE_URL` — отдельный тестовый сервер. WebKit-тест не заменяет проверку Safari на настоящем iPhone. GitHub Actions запускает три движка на Linux и отдельную сборку/HTTP-проверку Docker; публикация не выполняется.

Доступные лимиты: 25 МБ на файл, 30 файлов и 100 МБ на задание, до 12 мегапикселей на узком экране и 24 на большом, не более 16384 пикселей по одной стороне. Логотипы ограничены отдельно. В браузерах без Canvas-фильтров используется обработка пикселей полосами с ограниченной временной памятью.

`PUBLIC_EN_ORIGIN` и `PUBLIC_RU_ORIGIN` передаются в сборку Docker через аргументы Compose. Задавайте их перед пересборкой, если выберете другие домены. `SITE_ADDRESS` настраивает адреса Caddy. Ни DNS, ни публикация автоматически не изменяются.

## Приватность

Нет аналитики, счётчиков просмотров, внешних CDN и отправки содержимого файлов/полей. В localStorage записывается только тема. Офлайн-кеш содержит приложение, а не документы пользователя. Сервер и провайдер технически видят сетевые обращения и IP; в поставляемом Caddyfile журнал доступа не включён. Проверьте отдельно настройки прокси и провайдера.

Термин Zero-Knowledge описывает локальную обработку, а не криптографическое доказательство. Расширения, вредоносное ПО, скачанные файлы и буфер обмена вне контроля приложения. Для полного удаления темы и офлайн-копии очистите данные сайта в браузере.

Каждая сборка содержит `toolsiano-source.zip`, уведомления о лицензиях и SHA-256 в `build-info.json`. `work/` с временными файлами, `node_modules`, `.env` и журналы исключены из репозитория/исходного архива. Основной код распространяется под MIT; лицензии библиотек сохраняются. Полная техническая инструкция: [README.md](README.md).

Desktop UI: native-only collapsible navigation, optional settings/help disclosures and sticky primary actions. Windows x86 is a separate build with conservative memory limits; see src-tauri/README.md. Web layout is unchanged.
